# 4. Android project structure

The Android project is now [pda-android](../pda-android/README.md), with the complete requested layout in [STRUCTURE.md](../pda-android/STRUCTURE.md).

- Application: feature packages under presentation; domain/model, repository, scanner and usecase; data/remote, local, repository and mapper; infrastructure/firebase, alarm and device; di and common.
- Scanner libraries: scanner-api, scanner-zebra, scanner-urovo, scanner-generic and scanner-factory.
- Device libraries: device-api, device-android, device-zebra, device-urovo and device-factory.
- The app includes JVM tests, Android instrumentation tests and a bundled original alarm MP3.

Every module has its own Gradle configuration. API modules are plain Java libraries; platform/vendor adapters are Android libraries. AppModule holds API clients and services called directly by Activity/Fragment. HomeActivity retains Scan Order state across the product, image, inventory and disposal fragments.

# 5. Flyway SQL

Flyway runs automatically on backend startup. The six initial feature migrations (V1 through V6) define the 15 requested tables plus refresh sessions, durable outbox events and general audit records. V7 allows anonymous website finder requests by making requester_id nullable, in both fresh and legacy histories. Add subsequent changes as V8 and later; never edit an applied migration. Existing databases using the original single V1 select the preserved `db/legacy` history as described in the backend README. No passwords, inventory or product fixtures are inserted into production migrations. Integration tests insert isolated fixtures after migration.

# 6. Entity models

Domain models live in feature-specific `domain/*/model` packages. Application commands/results and HTTP DTOs are separate. Persistence entities, MyBatis mapper interfaces/XML, converters and repository adapters are under infrastructure. Repository ports are declared in domain and implemented by those adapters. Insert-only history tables are written through repository methods and queried as history rows. PKs for client-retried commands are UUIDs; internal ledger sequence IDs are BIGINTs. Monetary/quantity calculations use BigDecimal without floating-point conversion.

Every feature has its controller, use-case interface, application service, domain repository and MyBatis mapper. Product DTO mapping is generated by MapStruct. A user cannot choose an arbitrary store ID: the actor resolves the access token subject against the active database user.

Android screens call services directly, with shared Scan Order state in HomeActivity. Scanned products and selection are saved through onSaveInstanceState, bounded at 200 products to protect saved-state size. Adjustment navigation reuses the selection and only fetches its inventory; returning does not reload the scan list. Room caches product metadata and pending finder events. Glide manages image memory/disk caching. Device secrets and JWT pairs are AES-GCM encrypted with an Android Keystore key; backups are disabled.
