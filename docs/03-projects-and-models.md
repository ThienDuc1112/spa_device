# 4. Android project structure

The Android project is now [pda-android](../pda-android/README.md), with the complete requested layout in [STRUCTURE.md](../pda-android/STRUCTURE.md).

- Application: feature packages under presentation; domain/model, repository, scanner and usecase; data/remote, local, repository and mapper; infrastructure/firebase, alarm and device; di and common.
- Scanner libraries: scanner-api, scanner-zebra, scanner-urovo, scanner-generic and scanner-factory.
- Device libraries: device-api, device-android, device-zebra, device-urovo and device-factory.
- The app includes JVM tests, Android instrumentation tests and a bundled original alarm MP3.

Every module has its own Gradle configuration. API modules are plain Java libraries; platform/vendor adapters are Android libraries. AppModule composes repositories and services, while feature ViewModels depend on domain repository contracts and use cases. HomeViewModel retains Scan Order state across the product, image, inventory and disposal fragments.

# 5. Flyway SQL

Run Flyway automatically on backend startup. The initial migration defines all 15 requested tables plus refresh sessions, durable outbox events and general audit records. Never edit an applied migration; add `V2__...sql` for subsequent changes. No passwords, inventory or product fixtures are inserted into production migrations. Integration tests insert isolated fixtures after migration.

# 6. Entity models

`domain/Models.java` contains immutable read projections: User, Device, Product, Inventory, Disposal, DisposalItem, FindRequest, Refresh, Outbox and Actor. Insert-only history tables are written through repository methods and queried as history rows. PKs for client-retried commands are UUIDs; internal ledger sequence IDs are BIGINTs. Monetary/quantity calculations use BigDecimal without floating-point conversion.

Every feature has its controller, use-case interface, application service, domain repository and MyBatis mapper. Product DTO mapping is generated by MapStruct. A user cannot choose an arbitrary store ID: the actor resolves the access token subject against the active database user.

Each Android feature screen observes its own ViewModel, with shared Scan Order state in HomeViewModel. Scanned products and selection are saved through SavedStateHandle, bounded at 200 products to protect saved-state size. Adjustment navigation reuses the selection and only fetches its inventory; returning does not reload the scan list. Room caches product metadata and pending finder events. Glide manages image memory/disk caching. Device secrets and JWT pairs are AES-GCM encrypted with an Android Keystore key; backups are disabled.
