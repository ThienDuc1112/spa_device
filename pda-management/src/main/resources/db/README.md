# Script tạo schema Oracle 19c

Toàn bộ file `.sql` trong `migration` và `legacy` dùng cú pháp Oracle 19c. Đây là script khởi tạo schema mới, không phải script chuyển dữ liệu PostgreSQL sang Oracle.

## Cách chọn script

- Khuyến nghị: chạy `migration/V1` đến `V7` theo thứ tự phiên bản.
- Phương án gộp: chạy `legacy/V1__retail_schema.sql`, sau đó `legacy/V7__allow_web_finder_requests.sql`.
- Chỉ chọn một bộ. Hai bộ tạo cùng 18 bảng; không chạy chung trên một schema.
- `legacy` hiện cũng đã chuyển sang Oracle, không còn là bản migration PostgreSQL nguyên gốc. Không dùng các file đã sửa với lịch sử Flyway PostgreSQL đã áp dụng; checksum và dialect đều thay đổi. Cần giữ bộ migration cũ từ phiên bản ứng dụng trước cho database PostgreSQL hiện hữu.

## Quy ước kiểu dữ liệu

| PostgreSQL trước đây | Oracle |
| --- | --- |
| `BIGSERIAL` | `NUMBER(19) GENERATED BY DEFAULT AS IDENTITY` |
| `BIGINT` | `NUMBER(19)` |
| `UUID` | `VARCHAR2(36 CHAR)`, chuỗi UUID chuẩn có dấu gạch ngang |
| `VARCHAR(n)` | `VARCHAR2(n CHAR)` |
| `NUMERIC(18,2)` | `NUMBER(18,2)` |
| `BOOLEAN` | `NUMBER(1)` với CHECK chỉ nhận 0/1 |
| `TIMESTAMPTZ` | `TIMESTAMP(6) WITH TIME ZONE` |
| `now()` | `SYSTIMESTAMP` |
| `JSONB` | `CLOB` với `CHECK (payload IS JSON)` |
| `fcm_token TEXT` | `VARCHAR2(4000 BYTE)` để hỗ trợ unique index trực tiếp |

FCM token có giới hạn mới 4000 bytes. Các chuỗi bắt buộc không thể chứa chuỗi rỗng như giá trị khác NULL trong Oracle. UUID cần được bind/read dưới dạng chuỗi trong lớp persistence.

Index đều có tên. Unique index trên FCM token cho phép nhiều NULL. Index `one_active_find` dùng biểu thức CASE để chỉ giới hạn một request đang active cho mỗi thiết bị. Index `outbox_pending` chỉ chứa các bản ghi chưa processed.

Riêng `inventory_transactions`, unique index cho `(disposal_id, product_id)` chỉ áp dụng khi `disposal_id` khác NULL. Điều này tránh chặn nhiều lần điều chỉnh tồn kho của cùng sản phẩm do khác biệt về composite UNIQUE có NULL giữa Oracle và PostgreSQL.

## Giới hạn tích hợp hiện tại

Thay đổi này chỉ chuyển SQL tạo schema. `pom.xml`, datasource, MyBatis mapper/type handler và bộ integration tests của backend vẫn đang dùng PostgreSQL. Chạy ứng dụng với cấu hình hiện tại sẽ không áp dụng được các DDL Oracle này lên PostgreSQL.

Để backend chạy Oracle cần chuyển riêng JDBC driver/datasource, SQL truy vấn (`RETURNING`, `ON CONFLICT`, `LIMIT`, boolean, JSON...), xử lý UUID/generated keys và môi trường kiểm thử. Không chỉ đổi JDBC URL.

Chưa thực thi các script trên Oracle trong môi trường làm việc này. Trước khi sử dụng, chạy một bộ script trên schema Oracle trống và kiểm tra constraints/index, refresh token rotation, tồn kho và disposal với lớp persistence đã chuyển đổi.

Tham khảo cú pháp chính thức: [CREATE TABLE](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/CREATE-TABLE.html), [CREATE INDEX](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/CREATE-INDEX.html), [constraints](https://docs.oracle.com/en/database/oracle/oracle-database/19/sqlrf/constraint.html).
